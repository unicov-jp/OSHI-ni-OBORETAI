# 「推しに溺れたい」への作り直し計画

推し活手帳（ルートの `index.html`、1ファイルのWebアプリ）を、添付の「推しに溺れたい」（Next.js 16、この `web/`）を土台に作り直す。
切り替えるまでは、今の本番（推し活手帳）をそのまま動かし続ける。

## 決まったこと（依頼者の回答）

| 項目 | 決定 |
|---|---|
| 統合の方法 | 添付アプリ（Next.js）を土台に作り直し、推し活手帳の機能をすべて移す |
| アプリ名 | 推しに溺れたい（OSHI NI OBORETAI）。今の本番の表示名は変更済み |
| 取り込む機能 | 推しごとのSNS・Blog新着タブ、3Dのトップページ、3DのON/OFF（ONならトップ以外の画面も3D）、ダークモード、二段階認証、取得元の管理画面 |
| 新着の取得 | 毎日18:00（日本時間）に自動取得＋手動の「更新」ボタン |
| 上限 | 添付どおり。無料＝推し3人・SNS15件、有料＝推し50人・SNS300件。マスターは上限なし |
| 課金（Stripe） | 保留のまま（画面の表示は今と同じ「準備中」） |

## 制作側で決めたこと（変える場合は依頼者に確認する）

| 項目 | 判断 | 理由 |
|---|---|---|
| データ | 今の Supabase の表（`oshikatsu_records` など）をそのまま使う | 今の記録・設定・写真の参照を移し替えずに使い続けるため |
| 新着用の表 | `oshikatsu_` を付けて追加（`supabase/migrations/20261110000000_oboretai_feeds.sql`） | 添付の 0001_init.sql は public の全権限を外すため、そのままでは今のアプリが止まる |
| 運営者 | 今のマスター（`oshikatsu_profiles.plan = 'master'`）。運営者の画面と関数は二段階認証（aal2）必須 | ユーザー管理を一本化する |
| ログイン | 今のメール＋パスワードと Google の両方を残し、二段階認証（認証アプリ）を足す | 今メールでログインしている利用者がいるため |
| 推しの上限の強制 | 切り替えのときに別のSQLで入れる | 今のアプリの同期を、上限超えのエラーで止めないため |
| 画面の作り | 今と同じく端末に控えを持って同期する作り（オフラインでも見られる）を TypeScript に移す | 今の使い心地と、通信できないときの動作を保つため |

## 依頼者にお願いする作業

0. **推しの写真（残作業）**：確認用プロジェクト（oshi-ni-oboretai-next）の環境変数に、今の本番と同じ OAuth クライアント（oshi-ni-oboretai-drive）の `GOOGLE_OAUTH_CLIENT_ID`（Config）と `GOOGLE_OAUTH_CLIENT_SECRET`（Secret）を入れて Redeploy。設定画面（マスター）の「推しの写真」が OK になれば完了

1. **新着用のSQLの実行**（いつ実行しても今のアプリには影響しない。何度実行してもよいので、P1-c で関数を足した今の版を実行する）：`supabase/migrations/20261110000000_oboretai_feeds.sql`
2. **確認用の Vercel プロジェクトの作成**（作り直しの途中を本番と別のURLで見るため）
   - Vercel で同じリポジトリから新しいプロジェクトを作り、Root Directory を `web`、Production Branch を作業ブランチ（`claude/new-session-csr476`）にする
   - 環境変数：`NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`、`SUPABASE_SECRET_KEY`（秘密）、`CRON_SECRET`（秘密）、`NEXT_PUBLIC_SITE_URL`（確認用のURL）
3. **Supabase の設定**：Authentication > Multi-Factor で TOTP を有効にする。Authentication > URL Configuration の Redirect URLs に `https://<確認用のURL>/auth/callback` を足す
4. **Google の同意画面のアプリ名**：Google Cloud の OAuth 同意画面のアプリ名を「推しに溺れたい」に変える（ログインやドライブ接続のときに表示される名前）

## 切り替えのときに行うこと（P6）

- 推しの人数の上限を `oshikatsu_records` に入れるSQL（上限を超えている利用者は、新しく追加できないだけで今の推しは残す）
- 今の本番の Vercel プロジェクトの Root Directory を `web` に変え、環境変数を移す（`/api/config`・`/api/gdrive-token` は Next.js のルートに移植済みにしておく）
- 毎日18:00（日本時間＝09:00 UTC）の取得：`web/vercel.json` の cron を `0 9 * * *`
- 旧 `index.html`・`sw.js`・`api/` を撤去し、README を書き換える

## 注意

- Vercel の無料プラン（Hobby）の定期実行は1日1回まで。18:00 の1回と手動の「更新」で運用する。
- Googleドライブのフォルダ名「推し活手帳」は、保存済みの写真とバックアップを探すために変えない。
- 添付の共通UIルール（一覧の要素は文字数で大きさが変わらない）は、移す画面すべてに適用する。
